## 10. Per-seller lead-time heterogeneity (sellers with >=20 delivered items)

Lead time here = `order_delivered_customer_date - order_purchase_timestamp` (total purchase-to-delivery), attributed to each seller via `order_items`, restricted to the same valid/delivered population as section 9. This feeds the safety-stock reorder-point calculation in `build_features` (`lt_mean`, `lt_std`, `lt_p50`, `lt_p90`, `lt_n`).

- Sellers with >=20 valid delivered items: **873** / 2959 total sellers with any valid delivered item.
- Across those sellers, per-seller `lt_mean` ranges 4.66 to 31.73 days (median 12.03).
- Per-seller `lt_std` (within-seller variability) ranges 1.42 to 41.09 days (median 7.66).
- Cross-seller std of `lt_mean` = 3.35 days — confirms real seller-to-seller heterogeneity in fulfillment lead time (not just noise), which is why safety stock must be computed per-seller rather than from one marketplace-wide lead time.

## 11. Columns that do NOT exist in this dataset

**`Discount`, `Promotion flag`, and `Weather Condition` columns do not exist anywhere in the Olist dataset** (across all 9 tables). These existed only in the earlier Day-1 mock/scaffold built against a different, synthetic Kaggle dataset (`retail_store_inventory.csv`, see `src/data/loader.py` / `src/data/features.py` prior version). They must **not** be fabricated as proxies anywhere in the feature set (e.g. inferring a "promo" flag from a price drop, or a "weather" flag from `customer_state`/season). `src/data/features.py` (Olist version) contains no discount/promo/weather column under any name — this is asserted directly by `tests/test_features.py`.
