STOCKPILOT - NEON/POSTGRES SEED DATA
====================================

11 CSVs, one per table, numbered in the order they must be loaded so foreign
keys resolve. Generated by scripts/export_neon_seed.py from the real pipeline
output (data/processed/).

SETUP - run once, in this order:

  1. Create the schema
       psql "$DATABASE_URL" -f db/01_schema_base.sql
       psql "$DATABASE_URL" -f db/02_schema_extension.sql
     Both files are idempotent; re-running them is safe. If the 8 base tables
     already exist in Neon, 01 is a no-op and only 02 does anything.

  2. Load the data (run from inside this folder, \copy is client-side)
       cd neon_seed
       psql "$DATABASE_URL" -f load_order.sql

  Neon web editor alternative: import each CSV per table, in numbered order.

WHAT EACH FILE HOLDS

  01_stores               1   the marketplace (OLIST-BR)
  02_skus                50   seller-SKUs: stock, unit cost, lead time
  03_inventory_history 20177  REAL daily units_sold from Olist
  04_daily_forecasts    700   P10/P50/P90 + incumbent + actual + risk score
  05_users                2   PLANNER and ADMIN, for the approval workflow
  06_purchase_orders     50   AI recommendations with their full economics
  07_llm_audit_logs      50   Grok rationale + the evidence it reasoned over
  08_system_audit_trace 104   100 AI agent actions + 4 human approvals
  09_leadtime_forecasts  50   protection-interval quantiles (NOT additive)
  10_backtest_metrics     4   one row per rolling-origin fold
  11_simulation_runs      1   the three-arm cost comparison

HONEST CAVEATS

  * product_category is a placeholder ("General Merchandise"). Olist's category
    field is per-order and in Portuguese, not per-seller, so no mapping was
    forced.
  * inventory_history opening_stock / units_received / closing_stock are 0.
    Olist is a sales dataset with no stock ledger. units_sold is the real
    column; the others are structural zeros, not measurements.
  * Escalated recommendations load as status PENDING_APPROVAL.
  * prompt_tokens / completion_tokens are NULL - token counts live in Langfuse.
  * skus.rank_order preserves the pipeline's row order so the dashboard lists
    do not reshuffle when served from Postgres.

REGENERATE:  python scripts/export_neon_seed.py   (after `make plan`)
